# User Guide

## 1) Core Concepts

- Workspace: collaboration boundary (personal or team-style)
- Repository: Git code unit inside a workspace
- Issue: tracked work/problem/request
- Pull request: proposed branch merge into target branch
- Notification: activity/inbox event generated by platform actions

## 2) Typical Flow

1. Create workspace.
2. Create or import repository.
3. Push code via Git edge.
4. Open issues for work items.
5. Create branches and pull requests.
6. Review, comment, and merge.

## 3) Repository Usage

- Code tab:
  - browse tree
  - open files
  - edit/save (permission-dependent)
  - create file/folder from file mode `+` menu
- Issues tab:
  - filter by state
  - open issue detail
  - comment/update state (permission-dependent)
- Pull requests tab:
  - open/closed/merged filtering
  - PR detail conversation/checks/files
  - merge if policy/gating passes and user has rights

## 4) Permissions at a Glance

- Read-level: browse code/issues/PRs
- Write-level: push/create/edit issue/PR content
- Admin/owner-level: repo/workspace settings and access controls
- Platform admin (system-level): access to `/admin` operational controls

## 5) Notifications

- Bell icon shows unread state.
- Notification center supports read/unread transitions.
- Activity feed aggregates workspace/repo events.

## 6) Profile and Security

- Edit profile metadata and avatar.
- Review sessions and revoke old sessions.
- Manage notification preferences.
- Generate/revoke PATs in Developer settings.
